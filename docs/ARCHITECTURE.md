# Архитектура C-3PO Local Assistant

## Принципы

1. Локальная обработка по умолчанию.
2. Минимальные разрешения.
3. Явное подтверждение изменений.
4. LLM предлагает действие, но не выполняет его напрямую.
5. Интерфейс не имеет прямого доступа к shell.
6. macOS и Windows используют одно общее ядро там, где это возможно.

## Текущие слои

```text
┌──────────────────────────────────────────────┐
│ Vue 3 / TypeScript                           │
│ Voice-first UI, доступы, диалог, подтверждение│
└─────────────────────┬────────────────────────┘
                      │ Tauri invoke + JSON
┌─────────────────────▼────────────────────────┐
│ Команды Tauri                                │
│ Проверяемый интерфейс между UI и Rust        │
└─────────────────────┬────────────────────────┘
                      │ типизированный вызов
┌─────────────────────▼────────────────────────┐
│ Rust                                         │
│ Системная информация и будущий исполнитель   │
└──────────────────────────────────────────────┘
```

Роли персонажей разделены: C-3PO отвечает за интерфейс, голос и понятное общение с пользователем;
R2-D2 — имя локальной LLM, которая анализирует запрос и формирует текстовый ответ. Ни одна модель
не выполняет системные действия напрямую: разрешённую команду независимо проверяет Rust.

## Голосовой конвейер

Текущий конвейер:

```text
Микрофон → Web Speech API → текст → интерфейс → R2-D2/безопасная команда
Ответ R2-D2 → быстрый TTS ОС ИЛИ Chatterbox + приватный образец → динамики
```

Быстрый режим не загружает нейросеть и подходит компьютерам любой архитектуры. Тяжёлый TTS является
необязательным профилем и запускается только для режима «Мой голос». Он прогревается заранее, а
интерфейс делит длинный ответ на короткие смысловые части:
после получения первого WAV немедленно начинает его воспроизведение и одновременно запрашивает
следующий. Это конвейерная обработка, а не потоковое аудио внутри одного запроса, но она существенно
уменьшает время до первого произнесённого слова.

При запуске Rust формирует отчёт о платформе и нативных возможностях. WebView отдельно проверяет
runtime-разрешение микрофона и количество доступных аудиовходов. Это разделяет информацию о
возможностях сборки и фактически выданные пользователем права.
Положительное решение дополнительно запоминается в нативном JSON настроек: WKWebView на macOS может
после перезапуска снова сообщить `prompt`, хотя TCC уже сохранил разрешение.

На macOS системное распознавание речи включается только при запуске из пакета `.app`. В режиме
`tauri dev` интерфейс может получать уровень микрофона, но не создаёт `SpeechRecognition`: это
защищает от принудительного завершения процесса системой TCC, которая не принимает описание
разрешения распознавания от обычного исполняемого файла.

После замены распознавания целевая полностью локальная архитектура:

```text
Микрофон → захват PCM → whisper.cpp → текст → локальная LLM
         → безопасная команда → результат → локальный TTS → динамики
```

Образец текущего разработчика записан им самим. Публичный репозиторий не содержит записи: каждый
пользователь подключает собственный или лицензированный образец. Rust запускает отдельный Python-
процесс на `127.0.0.1:11438`, а CSP разрешает соединение только с этим loopback-адресом.

## Диагностика памяти

Rust возвращает текущий RSS процесса — объём физической оперативной памяти, фактически занятый
C-3PO. Интерфейс снимает показатель каждые пять секунд и показывает текущее, базовое и пиковое
значения. Устойчивый рост RSS при повторении одного сценария станет первым сигналом возможной
утечки. Виртуальная память сохраняется для диагностики, но не показывается как основной показатель:
на macOS WebKit резервирует очень большое адресное пространство, которое не равно реальному расходу
ОЗУ.

## Фоновый режим

Крестик перехватывается Tauri и скрывает главное окно. Tray-значок продолжает жить в строке меню,
открывает окно левым кликом и содержит явный пункт полного завершения. Голосовое пробуждение
принимает варианты `C-3PO`, `C3PO` и русскую транскрипцию; скрытое окно игнорирует речь без имени.
Команда после имени обрабатывается без открытия окна: сначала показывается уведомление о начале
анализа, затем уведомление с ответом. Одно имя открывает окно. На macOS для окна задано
`backgroundThrottling: disabled`, иначе скрытый WebView может приостановить голосовой цикл.
Тихий режим отключает микрофон и звук, оставляя историю и текстовый чат.
В скрытом состоянии регулярное выражение имени привязано к началу распознанной фразы: упоминание
C-3PO в середине постороннего разговора не активирует помощника.

Во время озвучки анализатор микрофонного уровня продолжает работать с системным эхоподавлением.
Устойчивая новая речь выше порога останавливает приватную фразу или сгенерированный WAV, отменяет
оставшуюся очередь воспроизведения и возвращает распознавание в режим слушания (barge-in).

## Контракт команды

Будущая LLM возвращает данные, а не shell-строку:

```json
{
  "action": "list_files",
  "arguments": {
    "path": "Documents"
  },
  "requires_confirmation": false
}
```

Rust проверяет название действия, аргументы, путь и требуемый уровень подтверждения. Неизвестная
команда отклоняется.

## Исполнитель приложений

`executor.rs` принимает не shell-строку, а одну из заранее известных операций. Запуск приложения
разрешён только для каталога Telegram, браузера, почты, файлов, заметок, календаря, калькулятора и
системных настроек. На macOS используется `/usr/bin/open -a`, на Windows — конкретный исполняемый
файл или зарегистрированный URI; пользовательский текст не становится командной строкой.

Сообщение Telegram является внешним необратимым действием. Интерфейс хранит структурированное
ожидание `{ contact, message }`, показывает оба значения и требует отдельного подтверждения. На
macOS Rust запускает константный AppleScript, а контакт и текст передаёт отдельными аргументами.
Для корректного ввода Unicode скрипт временно использует буфер обмена и восстанавливает прежнее
значение. Журнал содержит только длины полей, но не сообщение.

## Content Security Policy

Production-окно использует явную ограничительную CSP. Оно разрешает подключение к локальному TTS
на `127.0.0.1:11438` и воспроизведение сгенерированного `blob:` WAV. Режим разработки дополнительно
разрешает только Vite на `127.0.0.1:1420`; внешние адреса не добавляются.
