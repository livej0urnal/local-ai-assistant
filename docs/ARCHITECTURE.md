# Архитектура C-3PO Local Assistant

## Принципы

1. Локальная обработка по умолчанию.
2. Минимальные разрешения.
3. Явное подтверждение изменений.
4. LLM предлагает действие, но не выполняет его напрямую.
5. Интерфейс не имеет прямого доступа к shell.
6. macOS и Windows используют одно общее ядро там, где это возможно.

## Текущие слои

```text
┌──────────────────────────────────────────────┐
│ Vue 3 / TypeScript                           │
│ Voice-first UI, доступы, диалог, подтверждение│
└─────────────────────┬────────────────────────┘
                      │ Tauri invoke + JSON
┌─────────────────────▼────────────────────────┐
│ Команды Tauri                                │
│ Проверяемый интерфейс между UI и Rust        │
└─────────────────────┬────────────────────────┘
                      │ типизированный вызов
┌─────────────────────▼────────────────────────┐
│ Rust                                         │
│ Системная информация и будущий исполнитель   │
└──────────────────────────────────────────────┘
```

Роли персонажей разделены: C-3PO отвечает за интерфейс, голос и понятное общение с пользователем;
R2-D2 — имя локальной LLM, которая анализирует запрос и формирует текстовый ответ. Ни одна модель
не выполняет системные действия напрямую: разрешённую команду независимо проверяет Rust.

## Голосовой конвейер

Текущий конвейер:

```text
Микрофон → Web Speech API → текст → интерфейс → R2-D2/безопасная команда
Ответ R2-D2 → быстрый TTS ОС ИЛИ Chatterbox + приватный образец → динамики
```

Быстрый режим не загружает нейросеть и подходит компьютерам любой архитектуры. Личный TTS является
необязательным профилем: Apple Silicon использует MLX, остальные компьютеры — переносимый PyTorch.
Движок прогревается заранее, кэширует повторяющиеся фрагменты, а интерфейс объединяет соседние
предложения в связные блоки и делит только длинный ответ:
после получения первого WAV немедленно начинает его воспроизведение и одновременно запрашивает
следующий. Это конвейерная обработка, а не потоковое аудио внутри одного запроса, но она существенно
уменьшает время до первого произнесённого слова.

При запуске Rust формирует отчёт о платформе и нативных возможностях. WebView отдельно проверяет
runtime-разрешение микрофона и список доступных аудиовходов. Выбранное устройство сохраняется
локально; при его отключении интерфейс безопасно возвращается к системному микрофону. Это разделяет
информацию о возможностях сборки и фактически выданные пользователем права.

Официальный Tauri single-instance plugin регистрируется первым. Второй запуск передаёт управление
уже работающему процессу, который показывает и фокусирует окно `main`; второй WebView, микрофон,
LLM и TTS-процессы не создаются.
Положительное решение дополнительно запоминается в нативном JSON настроек: WKWebView на macOS может
после перезапуска снова сообщить `prompt`, хотя TCC уже сохранил разрешение.

На macOS системное распознавание речи включается только при запуске из пакета `.app`. В режиме
`tauri dev` интерфейс может получать уровень микрофона, но не создаёт `SpeechRecognition`: это
защищает от принудительного завершения процесса системой TCC, которая не принимает описание
разрешения распознавания от обычного исполняемого файла.

После замены распознавания целевая полностью локальная архитектура:

```text
Микрофон → захват PCM → whisper.cpp → текст → локальная LLM
         → безопасная команда → результат → локальный TTS → динамики
```

Образец текущего разработчика записан им самим. Публичный репозиторий не содержит записи: каждый
пользователь подключает собственный или лицензированный образец. Rust запускает отдельный Python-
процесс на `127.0.0.1:11438`, а CSP разрешает соединение только с этим loopback-адресом.

## Диагностика памяти

Rust возвращает текущий RSS процесса — объём физической оперативной памяти, фактически занятый
C-3PO. Интерфейс снимает показатель каждые пять секунд и показывает текущее, базовое и пиковое
значения. Устойчивый рост RSS при повторении одного сценария станет первым сигналом возможной
утечки. Виртуальная память сохраняется для диагностики, но не показывается как основной показатель:
на macOS WebKit резервирует очень большое адресное пространство, которое не равно реальному расходу
ОЗУ.

## Фоновый режим

Крестик перехватывается Tauri и скрывает главное окно. Tray-значок продолжает жить в строке меню,
открывает окно левым кликом и содержит явный пункт полного завершения. Голосовое пробуждение
принимает варианты `C-3PO`, `C3PO` и русскую транскрипцию; скрытое окно игнорирует речь без имени.
Команда после имени обрабатывается без открытия окна: сначала показывается уведомление о начале
анализа, затем уведомление с ответом. Одно имя открывает окно. На macOS для окна задано
`backgroundThrottling: disabled`, иначе скрытый WebView может приостановить голосовой цикл.
Тихий режим отключает микрофон и звук, оставляя историю и текстовый чат.
В скрытом состоянии регулярное выражение имени привязано к началу распознанной фразы: упоминание
C-3PO в середине постороннего разговора не активирует помощника.

Во время озвучки распознавание и анализатор микрофонного уровня продолжают работать с системным
эхоподавлением. Событие начала человеческой речи немедленно останавливает приватную фразу,
системный голос или сгенерированный WAV. Промежуточный распознанный текст и адаптивный порог
микрофона служат резервными сигналами на платформах с неполным Web Speech API. Прерывание отменяет
оставшуюся очередь воспроизведения и сохраняет новую фразу пользователя для обработки (barge-in).

## Контракт команды

Будущая LLM возвращает данные, а не shell-строку:

```json
{
  "action": "list_files",
  "arguments": {
    "path": "Documents"
  },
  "requires_confirmation": false
}
```

Rust проверяет название действия, аргументы, путь и требуемый уровень подтверждения. Неизвестная
команда отклоняется.

## Исполнитель приложений

`executor.rs` принимает название приложения как данные, а не shell-строку. На macOS исполнитель
сверяет его со Spotlight и стандартными каталогами `.app`; на Windows — с ярлыками установленного
меню «Пуск». Запускается только найденный пакет или системный URI. Пользовательский текст никогда
не интерпретируется оболочкой. Для неоднозначного частичного имени C-3PO показывает варианты и
просит назвать приложение точнее. Явные «Safari» и «Google Chrome» сохраняются разными целями.

Сообщение Telegram является внешним необратимым действием. Интерфейс хранит структурированное
ожидание `{ contact, message }`, показывает оба значения и требует отдельного подтверждения. На
macOS Rust запускает константный AppleScript, а контакт и текст передаёт отдельными аргументами.
Для корректного ввода Unicode скрипт временно использует буфер обмена и восстанавливает прежнее
значение. Журнал содержит только длины полей, но не сообщение.

Общий ввод в приложение использует типизированную команду `{ application, text, submit }`. Ввод без
отправки выполняется сразу; `submit=true` остаётся необратимой внешней границей и требует подтверждения.
На macOS исполнитель проверяет TCC «Универсальный доступ»,
активирует найденный `.app` и запускает константный AppleScript; пользовательские значения идут
только отдельными аргументами. Буфер обмена восстанавливается. Поисковые запросы кодируются в URL
и не проходят через shell.

Состояния Accessibility и Screen Recording читаются системными API
`AXIsProcessTrusted` и `CGPreflightScreenCaptureAccess`. C-3PO может открыть нужный раздел настроек,
но не выдаёт себе разрешение самостоятельно.

Каждое выполненное системное действие записывается в `logs/actions.jsonl`: тип операции, уровень
риска, решение пользователя, результат и безопасные технические метаданные. Тексты сообщений,
поисковых запросов и вводимых команд туда не попадают. Обычные ошибки остаются в `logs/c3po.log`.
Для созданных черновиков и событий Rust возвращает непрозрачный системный идентификатор. Интерфейс
хранит только последнюю запись отмены и вызывает отдельную проверенную обратную команду. Git для
системных приложений не используется; в будущем он подходит только для текстовых файлов внутри
явно выбранной пользователем рабочей папки.

## Инструментальный цикл модели

Актуальный вопрос сначала проходит через разрешённый Rust-инструмент, а не сразу через LLM. Для
погоды C-3PO выполняет ограниченный фоновый HTTPS-запрос к wttr.in; ближайший город определяется
сервисом по сетевому адресу. Системное приложение не запускается, доступ к экрану не требуется,
а текст команды наружу не передаётся. Наблюдение передаётся локальной модели отдельным системным
сообщением как данные, а не инструкция. Модель должна использовать полученные значения и не
выдумывать отсутствующие. Если LLM недоступна, интерфейс показывает исходную сводку инструмента.
Текущая системная дата, локальное время и часовой пояс добавляются к каждому запросу модели как
доверенное наблюдение. Прямые вопросы о сегодняшнем дне и времени обрабатываются средствами ОС без
участия LLM, поэтому модель не может придумать неверный день недели.

Почта и календарь используют отдельный `productivity.rs`. На macOS он обращается к Mail и Calendar
через системные Apple Events, поэтому окончательное разрешение всегда выдаёт macOS. Rust ограничивает
число и длину записей, интерфейс превращает их в недоверенное наблюдение, а локальная модель только
анализирует. Создание черновика и события проходит через типизированное ожидание, карточку проверки и
журнал действий. Текст письма в журнал не записывается.

## Локальный анализ файлов

Пользователь может приложить до 10 файлов через системный элемент выбора WebView. В этом сценарии
интерфейс принимает только текстовые форматы до 1 МБ и передаёт локальной модели ограниченный
фрагмент до 1700 символов; после отправки выбор очищается.

Командный файловый модуль разрешает поиск, чтение и перемещение только внутри канонического пути
домашней папки. Символические ссылки не позволяют выйти за эту границу. Чтение ограничено
проверенным списком текстовых и кодовых расширений, размером 2 МБ и контекстом 24 000 символов.
Перемещение и изменение имени используют атомарное переименование, отказываются перезаписывать
существующий путь и возвращают токен обратной операции. Удаление без отдельного подтверждения не
поддерживается.
Содержимое файлов не передаётся погодному сервису, журналу или другим внешним системам.

## Content Security Policy

Production-окно использует явную ограничительную CSP. Оно разрешает подключение к локальному TTS
на `127.0.0.1:11438` и воспроизведение сгенерированного `blob:` WAV. Режим разработки дополнительно
разрешает только Vite на `127.0.0.1:1420`; внешние адреса не добавляются.
